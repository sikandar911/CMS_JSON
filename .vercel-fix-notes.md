# Vercel Deployment Fix - Post Create/Update 500 Error

## Problem
- **Error on Vercel**: "Failed to create post" (POST) and "Failed to update post" (PUT)
- **Error on Vercel**: 500 status code returned without details
- **Root Cause**: Combination of two issues:
  1. **File system permissions**: Vercel serverless functions have read-only access to app root during runtime, but can write to `/tmp`
  2. **Poor error reporting**: Generic catch-all exceptions with no details being exposed

## Solution Implemented

### 1. Enhanced Error Logging in API Routes
- **Files**: `app/api/posts/route.ts`, `app/api/posts/[id]/route.ts`
- **Changes**:
  - Added detailed logging for JSON parsing errors
  - Added error details to response (for easier debugging)
  - Separated JSON parsing errors from database operation errors
  - Log full error stack trace for debugging

**Example**:
```typescript
// Parse request body
let body
try {
  body = await request.json()
  console.log('[POST /api/posts] Request body parsed successfully')
} catch (parseError) {
  console.error('[POST /api/posts] Failed to parse request body:', parseError)
  return NextResponse.json(
    { error: 'Invalid request body', details: 'Failed to parse JSON' },
    { status: 400 }
  )
}
```

### 2. Environment-Aware Data Directory
- **File**: `lib/json-db/connection.ts`
- **Changes**:
  - Detects when running on Vercel at **runtime** (not during build)
  - Uses `/tmp/cms-data` for write operations on Vercel
  - Uses local `data/` directory during build and local development
  - Added comprehensive logging for directory detection

**Detection Logic**:
```typescript
// Only use /tmp if on Vercel AND at runtime (VERCEL_URL set)
const isVercelRuntime = process.env.VERCEL === '1' && process.env.VERCEL_URL
if (isVercelRuntime) {
  return path.join('/tmp', 'cms-data')
}
// Otherwise use local data directory (for build and local dev)
return path.join(process.cwd(), 'data')
```

### 3. Improved File I/O with Better Logging
- **File**: `lib/json-db/connection.ts`
- **Changes**:
  - Added logging for directory creation attempts
  - Added logging for successful file reads
  - Better temp file cleanup on write failures
  - More descriptive error messages

## Why This Works

### For Local Development
- Uses `data/` directory as before
- No changes to workflow
- Full error details visible in terminal

### For Vercel Production
- First request to API (create/update post) will:
  1. Detect Vercel environment via `VERCEL` and `VERCEL_URL` env vars
  2. Create `/tmp/cms-data` directory if needed
  3. Write data to `/tmp/cms-data/posts.json`
  4. Subsequent requests in same execution can read/write from `/tmp`

### Important Note
⚠️ **Caveat**: `/tmp` is ephemeral on Vercel serverless functions. Each new function invocation gets a fresh `/tmp`. For persistent data storage on Vercel, you should:
- Use a database (PostgreSQL, MongoDB, etc.)
- Use Vercel KV (Redis)
- Use S3 or similar object storage

The current `/tmp` solution will work within a single request/response cycle but won't persist across invocations.

## Next Steps (Recommended)

For production use, consider:
1. **Database migration**: Move from JSON files to PostgreSQL/MongoDB
2. **Environment variable**: Add `DATABASE_URL` and update `lib/api.ts`
3. **Vercel KV**: Use Redis for cache and session storage
4. **S3 storage**: For media files and larger data
